## 2. 作らない資料と理由

| 資料 | 判断 | 理由 |
| --- | --- | --- |
| 要件定義書 | 不要 | 目的、利用者、範囲、受入の条件は設計書の1・2・7章にある。別に書くと二重管理になる |
| 基本設計書 | 不要 | 設計書がその役割を持つ |
| 画面設計書 | 不要 | 画面を作らない。Claude Codeの対話とMarkdownのメモだけである |
| ER図・クラス図・シーケンス図 | 不要 | 表は8つと分野の表、処理は1本道のCLIである。実装仕様書のDDLとモジュールの一覧で足りる。図を保守する時間に見合わない |
| API仕様書 | 不要 | 外部に提供するAPIはない。CLIの入出力は実装仕様書で定める |
| 運用手順書 | 不要（READMEに含める） | 利用者は記者1人で、手順は起動・調査・確認・公開だけである。リポジトリのREADMEに書く |
| 性能・可用性の設計 | 不要 | データは数千行で、1人が対話で使う。上限は設計書4.3で足りる |
| セキュリティ設計書 | 不要 | 設計書9.5と `claude_code_config.md` の設定で足りる |
| 移行計画 | 不要 | 既存のシステムがない |
| WBS・ガントチャート | 不要 | 3日分の作業順は設計書7.5と `implementation_prompts.md` の順で足りる |
| コーディング規約 | 不要 | ruffの設定と、実装プロンプト集の共通ルールの数行で足りる |
| 評価計画の別紙 | 不要（テスト計画に含める） | 評価ケースは6件と少ない |
| PRTRアダプタ仕様 | 今は不要（P1に着手するときに作る） | P0がすべて動いた場合にだけ着手する。先に書くと、実物を確かめないまま仕様が固まる |
