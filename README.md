# KIZASHI

調査報道のための AI エージェントです。オープンデータから見つけたニュースの端緒について、米アンソロピックの「Claude」が公開資料から理由を調べ、根拠をたどれる調査メモを作成します。計算・引用の照合・検証はプログラム（`kizashi`）が実行し、再現性を担保しています。意味づけと説明は Claude が担い、ニュース価値と採否は記者が決めます。調査メモは傾向を示すもので、不正の指摘ではありません。

- 設計：`docs/harness_design_m_v06.md`（設計書）
- 実装の仕様：`docs/implementation_spec.md`、内閣府のデータの仕様：`docs/adapter_cao_procurement.md`
- 決めたことと未決の点：`docs/decisions.md`
- デモ動画：準備中

## 名前の由来

「兆し」には、「物事が起ころうとする気配」のほかに、「草木の芽生え」という意味もあります。

KIZASHIは、ニュースの「ネタ（タネ、種）」を当事者や関係者から直接得るのではなく、公開データに潜む小さな変化を探り、その種が芽吹き、地上に顔を出したところを捉えるために開発されたAIエージェントです。

## 分野によらない仕組み

- **数値はコードが出す**：件数・金額・比率は Claude が計算せず、`kizashi` の算出結果を使用します。調査結果（メモ）の数値には「7,793,940円（令和6年度の合計。計算K0012）」のように計算IDが付き、そこから計算記録をたどれます。資料にない係数（税込と税抜の換算、按分、物価の補正など）は使わず、必要なときは記者に提案します。
- **原本に戻れる**：取得した資料は URL・取得日時を SHA-256 とともに保存し、書き換えません。引用は、原本から取り出したページ別のテキストと照合します。
- **否定できる形で調べる**：仮説ごとに取り下げ条件を先に調べます。変化の説明を6つの型（制度・定義の変更、集計範囲・期間の違い、業務・数量の変化、価格・市場の条件、主体の同一性、取り込み・公表形式・元の記載の誤り）に分け、一つずつ当てはめます。
- **検査に通った内容だけを調査メモにする**：8つの検証（数値の計算、引用と原本の照合、根拠、比較の条件、結論の要件、計算IDのない数値や個人の氏名の検査など）に合格した内容だけを記者に出力します。
- **すべて台帳に残す**：仮説・判定・計算・判断の履歴を、実行ごとの台帳（SQLite）に記録します。
- **権限を絞る**：調査のセッションで Claude が作成できるのは `inbox/` の提案ファイルのみ、実行できるのは7つの操作などに限定されています。
- **調査報道の知識を用いる**：知識ファイル（`references/`）として、オープンデータのカタログ、調査報道のノウハウ集（政治・公金・企業、暮らし・災害、海外、医療・福祉などの分野別の事例カード）、データ報道の事例・手法集の3点を持ち、調査中に ID で引きます。
- **分野ごとに最適化する**：取得の方法、列の意味、検出の SQL、原本照合の方法は、分野ごとのアダプタ（`datasets/<分野>/`）に分けることができます。分野を加えるときは、このアダプタを作成します。

## テストケース（実装と実証サンプル）

実データで調査メモまで作成したのは、内閣府の公共調達（競争入札・随意契約の契約の公表の CSV と PDF）です。分野の設定（`datasets/cao-procurement/dataset.yaml`）が対応しているのは令和5〜8年度のファイルで、令和8年度は年度途中として扱います。

現在実装している調査の型は、同じ種類の記録を連続した2年度で比べ、変化の理由を調べるものです。内閣府の分野では、契約金額・契約方式・随意契約の理由の変化を検出します。結論は「比較成立」「見かけの変化」「保留」のどれかです。

他には、環境分野（NITE の PRTR 個別事業所データ）のデータがあり、分野アダプタの骨組みだけを作りました。取得・正規化・検証から調査メモの作成までは通しておらず、CLI にも登録されていません。分野を増やした場合のサンプルです。

## 調査の流れ（内閣府の公共調達の例）

1. 記者と Claude が調べたい内容と比べる年度を決め、`kizashi run` で公表一覧のCSVとPDFを取得、品質を検査して、年度間の変化（契約金額、契約方式、随意契約の理由）の候補を検出します。
2. Claude が候補を最大3件選び、仮説と取り下げ条件を先にまとめ、公表資料（追加資料は最大12件）で理由を調べ、6つの型を一つずつ当てはめます。
3. `kizashi check` が8つの検証を行い、合格した内容だけを `kizashi render` が調査メモに出力します。

## 記者・Claude・`kizashi` の役割

| 誰が | すること |
| --- | --- |
| 記者 | 調べたい内容、比べる年度、母集団の絞り込み（指示するときだけ）を決め、係数の提案を使うか、企画化の是非、記事にするかを判断します。調査メモの「記者の確認リスト」の行で原本を確認できます |
| Claude（調査のセッション） | 候補を選び、仮説・同種業務の対応・主張・判定・取材質問・結論の案を、`inbox/` の提案ファイルに書いて `kizashi record` で登録します。`check` の不合格を読んで直します（修正は2巡まで） |
| `kizashi`（CLI） | 取得、正規化、品質検査、検出、計算、引用の照合、検証、メモの書き出し。台帳（SQLite）にすべての記録を残します |

## 必要なもの

- OS：macOS・Linux・WSL2（ネイティブの Windows は確かめていません）。開発は WSL2 で行いました。
- Python 3.13（リポジトリの `.python-version`）。標準ライブラリーの `sqlite3` が使う SQLite は 3.44 以上が必要です。3.44 未満なら、`kizashi` は起動時に `E_USAGE` で止まり、バージョンを示します。
- [uv](https://docs.astral.sh/uv/)（依存は `pyproject.toml` と `uv.lock` で固定）
- Claude Code（調査のセッション）。インストールしてログインし、`claude --version` でバージョンを確かめておきます。権限の設定を確かめた版は v2.1.318 と v2.1.319 です。
- 通信：取得は許可リストのホスト（`*.go.jp`、`*.lg.jp`）の HTTPS だけです。

## 導入

```text
git clone <このリポジトリの URL>
cd <クローンしたフォルダー>   # 以後の操作はすべてリポジトリの直下で行います
```

`uv run pytest` は通信を使いません。通信を使うテスト（`@pytest.mark.network`）は `uv run pytest -m network` で実行します。整形と静的検査は `uv run ruff check` と `uv run ruff format --check` で行います。

## 調査の始め方

調査は、リポジトリの直下で次のように起動します（開発には使いません）。

```text
scripts/investigate
```

`scripts/investigate` は、`uv sync --frozen` の後、Claude Code を次の設定で起動します。

- モード：許可したものだけが動く（`--permission-mode dontAsk`）
- 読む設定：プロジェクトの設定だけ（`--setting-sources project`）
- 使えるツール：Bash・Read・Grep・Glob・Skill・WebSearch・Write だけ
- 足す設定：`investigate.settings.json`（調査用）

このセッションの許可の一覧にあるのは、`inbox/` 直下の `.json` と `.sql` への書き込みと、Bash の `kizashi` の7つの操作（`run`・`fetch`・`inspect`・`query`・`record`・`check`・`render`）、Skill、WebSearch です。Skill は Claude に「Bash では kizashi だけを使い、ファイルを読むときは Read・Grep・Glob を使う」と指示しています。

ただし、Skill の指示と、実行が機械的に拒否されることは別です。拒否を実機で確かめたのは次の範囲です。

- `inbox/` の下のフォルダーや `.json`・`.sql` 以外への書き込み
- `src/`・`docs/`・`README.md` などへの書き込み
- `python3`・`curl`・`jq`
- 書き込みのできる Bash のコマンド。`docs/` への `cp` と `src/` への `touch`。

起動したら、次のどちらかで始めます。

```text
/investigate cao-procurement      # 新しい調査（分野を指定）
/investigate <run_id>             # 続きから（実行IDを指定）
```

流れ（`.claude/skills/investigate/SKILL.md`）：

1. Claude が `datasets/cao-procurement/README.md` を読み、記者とともに、調査内容と比べる2つの年度を決めて `inbox/run-config.json` を書き、`kizashi run cao-procurement --config inbox/run-config.json` を実行します。
2. `kizashi inspect <run_id>` で品質検査・検出の件数と候補の一覧を読み、詳しく調べる候補を最大3件選びます（選んだ理由を記者に伝えます）。
3. 候補ごとに、仮説と取り下げ条件、同種業務の対応、主張、6つの型の判定、取材質問を登録し、`kizashi fetch` で公表資料を取得して理由を調べます。
4. `review-lead`（Skill）で点検し、結論の案を登録して `kizashi check <lead_id> --run <run_id>` を通します。
5. `kizashi render <lead_id> --run <run_id>` で候補のメモを、`kizashi render <run_id>` で実行の概要を書きます。

記録はすべて `data/runs/<run_id>/` にあります：台帳 `ledger.sqlite`、品質レポート `quality_report.md`、登録した提案 `accepted/`、追加資料のページ別テキスト `evidence/`、メモ `memos/`、（一部内容を伏せた）写し `public/`。取得した原本は `data/raw/<sha256>.<拡張子>` に保存し、書き換えません。

## 調査メモの読み方

調査メモの候補は `data/runs/<run_id>/memos/<候補ID>.v<番号>.md`、実行の概要は `memos/run_summary.v<番号>.md` です。番号は書き出すたびに増え、前のメモは上書きしません。

冒頭の2行：

- 「調査用・記者未確認。調査の端緒であり、不正の指摘ではない。」——記者が確かめる前のメモであることを示します。`check` の合格や「検査済み」の主張は、記者の確認ではありません。
- 「調査用の設定で実行：はい／いいえ」——`scripts/investigate` の設定で実行したかを示します。同じ行に、実行ID、メモの番号、検証記録のハッシュも出ます。

| 節 | 載っていること |
| --- | --- |
| 1 状態と範囲 | 結論と説明の状況、問い、比べた年度、収録範囲、母集団の絞り込み（あれば記者の指示と条件）、使った公表一覧の資料、実行ID |
| 2 検出した変化 | 検出SQL、比べた値（計算ID付き）、年度の系列、比較の条件（母集団、1行の意味、期間、単位、主体の対応、算式）、比較できない理由、同じ区分の変化のほかの件数 |
| 3 照合済みの記載と計算 | 主張ごとの種類（原資料の記載・観測・公表元の説明・仮説）と根拠の位置、計算に加わったレコードと式、資料の一覧（資料ID・URL・取得日時・保存場所・SHA-256） |
| 4 説明の検討 | 6つの型の判定（支持・否定・未確認・対象外）と根拠・探した範囲、説明を反映した値と残る差、仮説と取り下げ条件の結果 |
| 5 言えないこと | このメモから言えないこと（定型文「CSVとPDFの一致は元の記載の正しさを示さない」を含む） |
| 6 次の取材質問 | 相手、問い、必要な資料、何が分かれば判断が変わるか、情報公開請求の候補 |
| 7 記者の確認リスト | 記者が原本で確かめる行。照合できなかった行と項目が先頭。CSV の保存場所、「NO」の値、表計算ソフトでの行番号の目安、PDF のページ、確かめる項目と値 |
| 8 再現情報 | 実行ID、規則の版、コードのコミット、モデルと Claude Code の版、Skill とルールのファイルのハッシュ（開始時と書き出しの時点）、検証記録のハッシュ |

結論の3種類：

- **比較成立**：比較を誤らせる説明（取り込み・公表形式の誤り、集計範囲・期間の違いなど）を否定でき、両年度の行が同種業務の対応で覆われている変化です。理由が分かったという意味ではなく、理由についての判断は下の「説明の状況」に示します。
- **見かけの変化**：集計範囲・期間の違い、主体の同一性、取り込みの誤り、公表形式間の食い違いのどれかが根拠付きで支持され、補正すると変化が消える、または同じ条件では比べられないと分かった変化です（例：単価契約、年度途中、様式の変更、法人番号の桁落ち）。
- **保留**：比較の条件を公開資料で確定できない、原本照合ができない、または探索の上限に達した場合です。足りない資料と、照会先・情報公開請求の候補が6節に出ます。

説明の状況（比較成立のとき）：**全部**（根拠のある説明で変化の全部を説明できる）、**一部**（残る差がある）、**範囲不明**（説明はあるが、どこまで説明できるかを確かめられない）、**なし**（公表資料に説明が見つからない）の4つです。

失効：メモを書いた後に台帳の中身（主張・判定・計算・資料の新しい版など）が変わると、`kizashi inspect <候補ID> --run <run_id>` がメモを「失効」と表示します。`check` と `render` をやり直すと新しい番号のメモができます。規則の版（`rules_version` など）が実行の記録と違うと、`check` と `render` は `E_RULE_VERSION` で止まります（新しい実行で調べ直します）。

## メモの読み直し（別のセッション）

`render` の後に、候補のメモを、読み取り専用の別のセッションで Claude に読み直させることができます。記者がリポジトリの直下で次のように起動します（開発には使いません）。

```text
scripts/review-memo <run_id> <lead_id>
```

- 最初の指示に、その候補の最新のメモ（`memos/<候補ID>.v<番号>.md` の番号が最大のもの）のパスと、資料のページ別テキストの場所（`evidence/<資料ID>/pages/<ページ番号>.txt`）を入れ、「否定の根拠が支えになっていない箇所、言い過ぎ、根拠の位置が主張を支えていない箇所を挙げる。書き込みはしない」と頼みます。指摘ごとに、メモの節、主張ID か型（T1〜T6c）、根拠の資料IDとページを書くよう頼んでいます。
- 起動の設定は `--permission-mode dontAsk --setting-sources project --tools "Read,Grep,Glob" --disallowedTools "mcp__*"` です。使えるツールを Read・Grep・Glob に絞り、`--tools` が効かない MCP のツールを別に拒否します。調査用の設定（`investigate.settings.json`）は読みません。最初の指示は `--` の後に渡します（`--tools` と `--disallowedTools` は値を複数取るため）。
- メモが失効していても起動します。起動の前に `kizashi inspect <候補ID> --run <run_id>` で、メモの状態が「有効」であることを確かめてください。
- 読めるのはメモとページ別テキストで、台帳（SQLite）は読めません。公表一覧の CSV の行を根拠にした箇所は、このセッションでは確かめられません（確かめられなかったと書くよう頼んでいます）。
- 同じモデルによる読み直しで、独立した検証ではありません。指摘は台帳に入らず、メモの根拠にもなりません。記者が指摘を読み、直すときは調査のセッション（`scripts/investigate`）で主張や判定を直し、`check` と `render` をやり直します。
- 引数の数か、実行ID・候補IDの書式が違うと終了コード2、実行のフォルダーかメモがないと終了コード3で、どちらも Claude Code を起動しません。

次の手順で、このセッションが書き込めないことと、MCP のツールがないことを確かめます。初めて使うときと、Claude Code の版を変えたときに行い、結果は版・日時・入力欄の下のモードの表示とともに `docs/decisions.md` に書きます。Claude は使ったツールを取り違えて報告することがあるので、Claude の返事ではなく、画面のツールの表示とファイルで確かめます。

1. 別の端末で、リポジトリの直下で `git status --short` を実行し、出力を控えます。
2. `scripts/review-memo <run_id> <lead_id>` で起動し、読み直しの返事を待ちます。その間に画面に出るツールの表示が Read・Grep・Glob だけであることを見ます。
3. `/permissions` の Deny のタブに、`mcp__*`（出どころが起動の引数）と、`--tools` に入れていないツール（Write・Edit・Bash・WebFetch など）が出ることを確かめます。
4. `/mcp` で、接続している MCP のサーバーを見ます。接続しているサーバーがあれば、`/context` の内訳に MCP のツール（`mcp__` で始まる名前）が出ないことを確かめます。サーバーが1つもなければ、MCP のツールがないことはこの手順では確かめられないので、記録に「未確認（MCP のサーバーなし）」と書きます。
5. 「リポジトリの直下に review-memo-test.txt を作り、test と1行書いて」と頼み、画面に Write・Edit・Bash などのツールの表示が出ないことを確かめます。Claude がモードの切り替えや `!` での実行を案内しても従いません。
6. `/exit` で終えてから、1の端末で、`git status --short` の出力が1と同じで、`ls review-memo-test.txt` がファイルなし（No such file or directory）を返すことを確かめます。

## 再現の手順と範囲（4種類）

再現を4種類に分けます。どれも、計算が一致しても解釈が妥当かは別に確かめます。

| 再現 | このリポジトリでの手順 | 範囲と制約 |
| --- | --- | --- |
| 保存した入力からの再計算 | 同じ実行で `kizashi check <候補ID> --run <run_id>` を行うと、メモの基礎集計を台帳で計算し直し（V3a）、原本を別経路の読み込み処理で数え直し（V3b）、派生計算をやり直し（V3c）、依存する資料の原本の SHA-256 を照らします（V2）。第三者は、合成データのテスト（`uv run pytest`）で、計算の手順を手で求めた期待値と照らせます | 原データ（`data/`）は公開しません。テストにも実データの抜粋を入れず、合成データだけを使います。そのため第三者にとっては「計算の手順は追試できるが、同じ実データの取得は保証できない」ことになります。保存した原本から実行を作り直す操作（取得の代わりに `data/raw` を読む）はありません（`run` は公表元から取得します）。原データの誤りは別の問題です |
| 公開元からの再取得 | 同じ実行設定（`data/runs/<run_id>/accepted/` の最初の `run_config`）で `kizashi run` を行い、メモ3節の資料の一覧の SHA-256 と比べます。実行の中で1つの資料を取り直すときは `kizashi fetch <run_id> --recheck <資料ID>` を使います | 内閣府のファイルは毎月差し替わるため、同じ版を再取得できないことがあります。差は新しい版として記録し、古い版に依存する候補のメモは失効と表示されます。公表一覧の新しい版は、その実行では正規化しないので、新しい実行で調べ直します |
| 台帳からのメモの書き出し | 同じ台帳で `kizashi render <候補ID> --run <run_id>` を行います | 同じ台帳とテンプレートから、同じ本文と引用の対応が出ます（検証記録のハッシュも同じです）。メモの番号、書き出しの時点の Skill のハッシュなどの付帯情報は違います。規則の版が違えば `E_RULE_VERSION` になります |
| Claude による調査の再実行 | 同じ問いで `scripts/investigate` から調べ直します。メモ8節と台帳に、モデル、Claude Code の版、Skill とルールのファイルのハッシュ、登録した提案（`accepted/`）、判断の履歴（`events`）が残ります | 探索の経路や文章の一致は保証しません |

## 公開の手順と、公開しないもの

公開する生成物の例は、次の順で用意します。

1. 記者が `render --public` の伏せた写しから選んで `examples/` に置き、`examples/publish.manifest` に書きます。
2. 公開用のコミットを手元で作ります（この時点では push しません）。
3. そのコミットで `kizashi check --publish` を通します。検査は最新のコミットの一覧との一致を求めるので、コミットの前は不合格になります。
4. 通ったそのコミットを公開します。

手順、`disclosure.allow`（伏せない名前。記者が指定）、補助資料の一覧（`KIZASHI_DENYLIST`。4点を1行ずつ）の書き方は `examples/README.md` にあります。**公開するのは、`check --publish` を通したコミットそのもの（検査の後に変えていないもの）だけにします**。

検査は `examples/` だけでなく、ステージと、すべての参照からたどれる履歴の中身も見ます。履歴で見つかったものは作業フォルダーを直しても消えないので、新しいリポジトリを作り直します。氏名・受注者名などを検査するのは UTF-8 として読めて 5MB 以下の中身だけで、それ以外（Shift_JIS の CSV、PDF など）はハッシュだけを照らします。合格のメッセージにその数が出るので、0件でなければ記者が中身を確かめます。

検査が見るもの：

- 一覧（`examples/README.md` と一覧のファイル自身）と、ステージ・最新のコミットの `examples/` の一覧が一致するか。
- `KIZASHI_DENYLIST` の4点の中身の SHA-256 が、作業フォルダーの一覧のファイル・ステージ・履歴のどの中身とも一致しないか。4点のファイル名が、ステージと履歴のパスにないか。
- `--run` で指定した実行の原本と台帳から作った氏名・取り込まない列の値・受注者名・法人番号が、ステージと履歴のテキストにないか。この中には `docs/`、`references/` の知識ファイル、テストも入ります。

公開している生成物の例と、その検査の記録は `examples/README.md` にあります。

公開するものと、公開しないもの：

| 公開するもの | 公開しないもの |
| --- | --- |
| コード、`CLAUDE.md`、Skill、設定の例、分野アダプタ（`datasets/`）、テスト（合成データ）、評価の方法と結果（`eval/`）、記者が選んだ生成例と実行記録（`examples/`）、知識ファイル3点（v13.0。SHA-256 は「知識ファイル」の節）、README | 原データそのもの（利用条件の確認が済むまでは取得手順とハッシュだけ）、`data/` と `inbox/`、補助資料4点（設計時に参考にした調査資料）、APIキー、個人の氏名、内部用の列（担当官の所在地・相手方の住所など）、会話の全履歴、未確認の実名の仮説、個人の絶対パス |

公開する例とデモ動画では、受注者名と法人番号を既定で伏せます。記者未確認のメモで実在の企業を名指しすることの影響を避けるためです。引用には、候補と関係のない受注者名や法人番号が入ることがあります（一覧表のページの引用は、文末までの決まりで長くなります）。伏せ字と `check --publish` が当てるのは、その実行の公表一覧にある受注者名・法人番号と同じ文字列だけなので、表記の違う名前や公表一覧にない名前は伏せられません。公開する写しとデモ動画では、引用の中の名前も記者が確かめます。

## 限界

- 理由をたどる資料（公告・仕様書など）が公開されているとは限りません。理由を調べる資料の経路は未決です。見つからなければ、見かけの変化と保留を中心にし、誤った比較を止めることを価値として示します。
- 点検（`review-lead`）は調査と同じ文脈で行うので、独立した読み直しではありません。独立した確認は、別経路の再集計（V3b）と記者が担います。別のセッションでの読み直し（`scripts/review-memo`）も同じモデルによるもので、独立した検証ではありません。
- 強い語（「不正」「疑惑」など）は警告だけで、書き出しを止めません。表現の行き過ぎは記者が確かめます。
- 比較の条件を確定できない候補で、1つの年度の値だけを参照して文で比べる主張は、機械の検査（V5）では見分けません。`review-lead` が点検し、メモの7節で記者が確かめます。
- 権限の設定は、許可した `kizashi` の中の処理には及びません。`kizashi` は入力の場所・拡張子・パスを検査しますが、OS の水準の制限（サンドボックス）は入れていません。試したところ、共通設定の `Edit(/data/**)` の拒否がサンドボックスにも効き、`kizashi run` が台帳を書けませんでした。取得した資料の中の指示（プロンプトインジェクション）を完全には防げません。テストの SF-1 は、資料の中の指示で `kizashi` の台帳や設定が変わらないこと（取得の処理）を確かめたもので、資料を読んだ後の Claude の振る舞いは試していません。
- 内閣府のファイルは同じ URL のまま差し替わることがあります。`fetch --recheck` で取り直してハッシュを比べます。
- 知識ファイルに誤りや版の更新がありえます。メモの根拠にはしません（V2）。
- 追加資料のページ別テキストでは、実行の担当官の氏名（公表一覧の担当官の列にある氏名）を「（氏名）」に替えて保存します。それ以外の氏名は伏せられません。`check` は、引用したページ別テキストを原本から抽出し直して比べ、文書値を引用の数値と照らし直します。台帳や `data/` を直接書き換えた場合の検出は、この2つと原本の SHA-256（V2）、計算のやり直し（V3）の範囲に限ります。
- 調査のセッションの Claude が、使ったツールを取り違えて報告することがあります（Read で読んだのに「tail を実行した」と返しました）。操作を確かめるときは、画面に出るツールの表示（Read・Bash など）で確かめます。
- 「記者未確認」のメモが確かめられないまま使われるおそれがあります。冒頭の定型文と記者の確認リストで示し、公開は記者が一覧を作り検査を通した場合だけにします。
- 上限：詳しく調べる候補3件、追加資料12件、通信40回、修正2巡。上限に達したら保留にします。
- 評価（`eval/`）の件数は多くありません。AIによる確認（照合・評価）を一部行っただけで、人による確認は行っていません（`eval/summary.md`）。精度の数字は主張しません。
