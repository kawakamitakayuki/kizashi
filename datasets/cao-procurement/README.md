# 内閣府の公共調達（cao-procurement）

調査を始める前に読む分野の要点。詳しい仕様は `docs/adapter_cao_procurement.md`、取得と列の対応は同じフォルダーの `dataset.yaml`。このファイルは手がかりで、メモの根拠にしない（数値は kizashi の計算から出す）。

## 対象
- 内閣府「公共調達の適正化について」に基づく、競争入札と随意契約（物品・役務等）の公表データ。公表ページは `https://www.cao.go.jp/chotatsu/kohyo/kohyo.html`。月1回更新され、過去の年度のファイルも差し替えられうる。
- 公表ページは「PDF形式とCSV形式のデータは同一のものです。」と注記している。kizashi は CSV を取り込み、全行を PDF と照合する（T6b）。CSV と PDF の一致は、元の記載が正しいことを示さない。

## 年度
- 比べるのは令和6・7年度（`compare_years` の既定 `[2024, 2025]`）。令和5年度（2023）は系列として読む（`series_years` の既定 `[2023, 2024, 2025]`）。
- 令和5年度を比べない理由：随意契約の理由の分類が `other` になる行が多く、書式の違いによる見かけの候補が増える。
- 令和8年度（2026）は年度途中のデータ。読めるが、比べると比較できない理由に `partial_year` が付く。
- `dataset.yaml` の `files` にない年度を `run_config` に書くと `E_SCHEMA`。

## 比較の単位
- 1行は1件の契約。年度は契約を締結した日の会計年度。
- 同種業務の候補は、件名から年度・期・月分などの表記を除いた「件名のまとめのキー」（`group_key`）。除いた文字列は `title_removed_parts` に残る（業務量の変化を見落とさないため）。名称が似ているだけで同種と決めない。同種の確定は `kind: match`（`confirmed`）で行う。
- 検出は3本：S1 契約金額の合計の変化（`amount_up`・`amount_down`、片方の年度に合計できる行がなければ `amount_incomparable`）、S2 契約方式の変化（`kyoso_to_zuikei`・`zuikei_to_kyoso`）、S3 随意契約の理由の変化（`reason_changed`。理由の分類と根拠条文の組）。S2・S3 は件数だけで、金額の合計を作らない。
- 方式は `method_family`（`kyoso` 競争入札・`zuikei` 随意契約）。理由の分類は `reason_category`（`planning_competition` 企画競争、`failed_tender` 不調、`open_call` 公募、`nature_no_competition` 競争を許さない、`charity` 慈善、`other`）。
- calc で使える表は `procurement_contracts`、合計できる列は `amount_yen` だけ。条件に使える列は `fiscal_year`・`method_family`・`group_key`・`unit_price`・`reason_category`・`corp_number_state`・`dup_group`・`record_id`。

## 注意点
- 単価契約：方式の列か金額の列に「単価」を含む行は `unit_price = 1`。片方の列だけを見ると見落とす。金額の合計から除き、S1 の除いた行に理由 `unit_price` で出る。
- 数値にならない金額（空欄、外貨、単価の書き方、そのほか）は `amount_yen` が空。0円にせず、合計から除く（理由 `amount_not_numeric`）。
- 法人番号：CSV の指数表記（`\d\.\d+E\+\d+` の形）は桁が失われている。復元しない。名寄せは13桁の法人番号で行い、名称の一致は候補にとどめる。指数表記は競争入札の全年度と随意契約の令和5・6年度にあり、令和7年度の随意契約は13桁。指数表記の行のうち、同じ年度・方式の PDF の法人番号の欄の13桁が、検査用数字・指数表記に残る有効桁・件名と金額の一致の3条件をすべて満たすものだけ、`run` が `corp_number_state = 'valid_from_pdf'` にして13桁を入れる（設計書7.4。D-076・D-077）。満たさない行は `exponent` のまま（未確定）で、同一法人として数えない。どちらの行かと満たさなかった条件は、原本照合の記録（`inspect` の計算ID）の行の `corp_completion` にある。補完した13桁は PDF の値で、CSV では有効桁までしか確かめられないので、T6b の法人番号の照合は `unverifiable` のまま。
- 担当官の所属：3列目は契約担当官の所属で、発注を求めた部局とは限らない。令和6・7年度では、約4分の3の契約を会計担当の参事官が結んでいる。所属で絞れるのは、部局ごとの契約担当官がいる一部の部局だけ。メモでは「契約担当官の所属」と書く。業界で絞る列はない。どちらも、件名の語で近似するかを記者に確かめる。
- 氏名：担当官の氏名は取り込まず、`inspect` にも出ない。どの提案にも氏名を書かない。公表一覧の PDF にはページ別テキストがないので、その記載は同じ年度・方式の CSV の `row_ref` で引用する。公表一覧の CSV・PDF は追加資料として取得できない（`E_BAD_EVIDENCE_SOURCE`）。
- `?`：PDF の文字が `?` に置き換わったセルがある（相手方の名称など）。直さずに元の値として扱い、原本照合では不一致になる。
- 重複：NO 以外が同じ行の組には `dup_group` が付き、比較できない理由 `duplicate_rows` になる。黙って除かない。日付を読めない行は `bad_date`。
- 予定価格と落札率は、P0 では指標にしない。
- 随意契約の理由の欄は、原資料の記載として示す。説明（T1〜T5）の支持の根拠にしない。

## 理由を調べる資料
- 確かめた経路（`docs/decisions.md` の D-004）：部局（担当室など）が会議資料として公表している、年度ごとの契約実績報告。PDF を `kizashi fetch` で取得し、ページ別テキストから引用できた。前年度と同じ契約であることや、契約方式を決めた経緯についての部局の説明が書かれていることがある。裏付けられるのは、その記載が述べる範囲まで（同種業務の対応の手がかり、部局の説明）で、仕様・数量・成果物が同じことまでは言えない。説明は誰の説明かを書く。
- 案件ごとに取れるかを確かめるもの：入札公告・仕様書（調達ポータルなど）。取得していないものを取得した扱いにしない。取れなければ未確認の問いとして残し、取材質問か情報公開請求の候補にする。
- そのほかの代わりの候補（未確認）：契約公表の注記、随意契約の理由（原資料の記載として示すだけで、支持の根拠にしない）、調達ポータルの調達公告（総覧 D073）、行政事業レビューシート（総覧 D059）。
- 取得できるのは `dataset.yaml` の `fetch.allowed_hosts` のホストだけ。
- 6つの型の、公共調達での例（設計書5.4）：T1 公表基準・契約規則・通達の改正。T2 年度途中、様式・列の変更、単価契約、片方の資料だけにある案件。T3 仕様・数量・期間の変更、事業の統合・分割、複数年契約。T4 物価・税の扱い、供給者が少ない専門分野。T5 受注側の商号変更・合併、発注側の部局の再編、法人番号の未確定。T6a・T6b は kizashi が照合の結果から判定する。T6c 原表の入力ミス、訂正版の公表。

## このファイルに書かないもの
- 実データの受注者名（相手方の名称）と法人番号。例が要るときは架空の値にする。
